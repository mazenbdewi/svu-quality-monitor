# تشخيص النظام — System Diagnostics

افتح **تشخيص النظام** من لوحة الإدارة (`/admin/system-diagnostics`). تعرض الصفحة
ملخص الجاهزية ووقت حسابه؛ زر **إعادة الفحص** يحسبه مجددًا دون إصلاح تلقائي.
رابط التفاصيل يفتح System Operations التي تبقى للتفاصيل التشغيلية.
الوصول بصلاحية `operations.view`: Operator وAdministrator وSuper Admin بحسب
المصفوفة الحالية، وليس Viewer. يُعاد التحقق من الصلاحية عند إعادة الفحص.

## ما الذي يُفحص؟

- التطبيق: البيئة وDebug وإصدارات PHP وLaravel والتطبيق إن توفر.
- قاعدة البيانات: اتصال محلي، المحرك والإصدار، والترحيلات غير المنفذة.
- الفحص التلقائي والمعالجة الخلفية: `SystemHealthService` نفسه، بنفس Runtime
  Heartbeats والحدود؛ أعداد المهام من الخدمة نفسها. الأعداد غير المتاحة تستدعي تحذيرًا.
- نشاط المراقبة: آخر فحص تلقائي مخزن لخدمة مفعلة. غيابه أو قدمه بأكثر من ضعفي
  أكبر فترة فحص للخدمات المفعلة يستدعي تحذيرًا؛ عدم وجود خدمات مفعلة سليم.
  هذا مؤشر نشاط إجمالي، وليس ضمانًا لحداثة كل خدمة؛ تفاصيل الخدمات في صفحات المراقبة.
- النسخ: `BackupService::health()` دون تغيير قواعده؛ آخر نجاح وفشل وعمر النسخة.
  النجاح يعني أن النسخة اجتازت التحقق عند إنشائها، وليس إعادة تحقق من محتواها الآن.
  جاهزية منفصلة لمجلد النسخ القابل للكتابة وتوفر الإعدادات والأوامر، لا ضمان نجاح restore.
- الأمان: وجود Super Admin فعال، الأدوار الأربعة وصلاحية التشغيل عبر Spatie،
  ووجود جدول التدقيق وإمكان قراءة صف منه. لا تُعرض أسماء المستخدمين.
- التنبيهات: Disabled سليم؛ Enabled دون إعداد كامل تحذير. Telegram يحتاج token
  وchat ID؛ Email يحتاج مستلمًا صالحًا ومرسلًا وإعداد SMTP. النواقل الأخرى تستدعي
  تحققًا يدويًا ولا يُدّعى أنها جاهزة. لا يثبت الفحص صلاحية credentials أو قابلية التسليم.
- التخزين: صلاحيات storage وframework/cache؛ اختبار cache بمفتاح عشوائي مؤقت
  يُحذف في finally وله TTL لمدة 60 ثانية. مساحة storage ومجلد النسخ بـGB، وتحذير
  تحت `config('diagnostics.minimum_free_bytes')` (افتراضيًا 1 GiB، قابل للضبط عبر
  `DIAGNOSTICS_MINIMUM_FREE_BYTES`). المجلد المفقود لا يُنشأ تلقائيًا.

## معنى النتيجة

- **جاهز / Ready:** كل الفحوص سليمة.
- **يحتاج انتباهًا / Needs Attention:** تحذير، أو تعطل مكوّن غير حرج مثل النسخ
  أو إعداد قناة تنبيه، دون تعطل مكوّن حرج.
- **غير جاهز / Not Ready:** تعطل DB أو Scheduler أو Queue أو storage/cache أو
  عدم وجود Super Admin أو خلل RBAC/audit. جميع الترحيلات المعلقة تُعامل كمانع
  جاهزية تحفظيًا، لأن خطورتها لا تُستنتج آليًا. Debug في production تحذير.

القواعد مركزية في `SystemDiagnosticsService`؛ لا نسب أو متوسطات وهمية.
الفحص الذي يرمي استثناءً يظهر متوقفًا مع رسالة عامة، ولا يمنع حساب بقية الفحوص.

## ما لا يُنفّذ عمدًا

لا مسح شبكة أو SSL أو APIs خارجية، لا رسائل اختبار، لا backup/dump/restore أو
verify كامل، لا seeding أو migrations أو إصلاحات، ولا أحداث تدقيق وهمية.
لا Docker socket ولا تغيير للمعمارية؛ لا أسرار أو مسارات حساسة أو استثناءات خام
في HTML أو حالة Livewire. نسخة الصفحة ثابتة حتى الضغط على إعادة الفحص.
فحص الصلاحيات ومساحة القرص ليس اختبار كتابة ملف كبير أو اختبار سلامة القرص.
الصفحة تعتمد على إمكان تشغيل Laravel وتسجيل الدخول: انقطاع DB كلي يمنع
المصادقة/الجلسات أو الـTopbar الحالي قد يمنع فتح اللوحة أصلًا؛ ليست بديلًا عن مراقبة
خارجية أو `system:smoke-check` من سطر الأوامر عند تعطل الواجهة.
