# Batch 4A read-only service quality overview

The existing Performance Analysis page hosts the overview; no new primary navigation item or SLO lifecycle action is introduced. A researcher with the existing `reliability.view` permission selects an HTTP/API service and explicitly loads the overview; the original `control_charts.view` page permission still applies. Draft, reviewed, and retired proposal details additionally require the existing `slo.proposals.manage` research permission; approved targets remain readable to reliability viewers. This avoids running the fixed 28-day percentile query on ordinary dashboard or page renders. The calculation timestamp is stored in UTC and displayed in the institution timezone, making retained Livewire state visible; the refresh button requests a new read-only calculation. The cards use responsive grids and the existing Arabic/English locale mechanism. Loading and analysis-error states do not imply a healthy result.

Screenshots from a disposable local SQLite demonstration: [English](screenshots/batch-4a-en.png) and [Arabic](screenshots/batch-4a-ar.png). These are illustrative data, not production measurements.

| Display | Source and period |
| --- | --- |
| P50/P90/P95/P99, valid latency count, 28-day coverage and missing opportunities | `LatencyPercentileAnalysis::analyze()`; latest 28 complete institution-local days, UTC half-open window. Successful eligible automatic HTTP/API checks with valid nonnegative latency only enter percentiles. |
| Availability S/N, conditional latency G/V, combined success-latency G/N | Existing `SliIndicatorAnalysis::describe()` when no evaluation exists (threshold null, so G/V and G/N are null); otherwise the selected frozen-objective `SloEvaluationAnalysis` result. Displayed numerators and denominators identify the basis. |
| Proposal lifecycle, calibration period/cutoff, policy, historical P90/P99, target, rounding, warnings | Frozen `SloProposal.calibration_payload`, verified by `SloProposalService::assertIntegrity()`; authorized researchers see the latest proposal separately from the latest approved proposal, while other reliability viewers see approved research details only. No recalibration occurs when the page opens. |
| Retrospective and prospective target comparison | `SloEvaluationAnalysis::evaluate()` using the latest approved objective. The retrospective window ends no later than approval and is bounded to 28 elapsed days; the prospective window starts at the first complete local midnight strictly after approval and cutoff and is bounded to 28 local days. Incompatible configuration or inadequate coverage yields insufficient evidence, not an asserted pass/failure. |
| SPC deterioration state | Existing approved Phase I baselines and current live Phase II evaluation, point, and signal records, with the same conservative state conditions used by Early Deterioration Detection. The detail page remains the source for full chart context. |

These are synthetic monitoring checks, not browser page-load measurements or TTFB. The provisional 99% combined target is project research policy, not a Google-mandated limit. Current-cadence coverage is an estimate; missing opportunities are never treated as healthy observations. P99 tail uncertainty and incomplete historical configuration reconstruction remain limitations. The page issues bounded queries only when the overview is explicitly loaded, but it does not offer cross-request caching; calculation time is shown so the user can decide when to refresh. There is no database migration or write path in this batch.
